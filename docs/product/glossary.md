# FlowCore Glossary

**Version:** 1.0  
**Status:** Draft  
**Last Updated:** 2026-08-02

---

# User

A registered person who can access the FlowCore platform.

A user may belong to one or more organizations depending on their permissions.

---

# Organization

An isolated workspace representing a company or business.

Organizations contain projects, members, forms, requests, integrations, and settings.

---

# Member

A user who belongs to an organization.

Each member has one or more roles that define their permissions.

---

# Tenant

An isolated organization inside the multi-tenant architecture.

Data belonging to one tenant must never be accessible by another tenant.

---

# Role

A collection of permissions assigned to organization members.

Examples:

- Owner
- Administrator
- Manager

---

# Permission

A specific action that a user is allowed to perform.

Examples:

- Create Project
- Delete Form
- Manage Members

---

# Project

A business unit inside an organization.

Each project contains its own forms, requests, workflows, and integrations.

---

# Form

A configurable structure used to collect customer information.

Forms may contain different field types and can be published publicly.

---

# Form Field

A single input element inside a form.

Examples:

- Text
- Number
- Email
- Phone
- Date
- Select

---

# Form Version

An immutable snapshot of a published form.

Publishing a form creates a new version without modifying previous ones.

---

# Submission

A customer request submitted through a public form, Telegram bot, or API.

Each submission is stored inside the CRM.

---

# CRM

The internal request management system.

CRM allows users to:

- view requests
- assign managers
- change statuses
- add comments
- monitor history

---

# Workflow

A sequence of automated actions executed after a specific event.

Example:

New Submission

↓

Send Telegram notification

↓

Save to Google Sheets

↓

Assign Manager

---

# Integration

A connection between FlowCore and an external service.

Examples:

- Telegram
- Google Sheets
- Email
- Webhooks

---

# Telegram Bot

A connected Telegram application that communicates with customers and submits requests to FlowCore.

---

# Google Sheets Integration

An integration that automatically synchronizes submissions with Google Sheets.

---

# Audit Log

A chronological record of important system events.

Audit records cannot be modified.

Examples:

- User login
- Project creation
- Role change
- Form publication

---

# Notification

A message generated by the system after a specific event.

Notifications may be delivered through:

- Telegram
- Email
- Webhooks

---

# API

The public REST interface used by clients and integrations to communicate with FlowCore.

---

# Module

A self-contained business component of the application.

Examples:

- Identity
- Organizations
- Projects
- Forms
- CRM
- Workflows

Each module owns its business logic and data.

---

# Domain

The business layer that contains entities, business rules, and domain logic.

The domain layer must not depend on infrastructure or frameworks.

---

# Application Layer

The layer responsible for coordinating business use cases.

It connects the API with the domain layer.

---

# Infrastructure Layer

The layer responsible for communication with external systems.

Examples:

- PostgreSQL
- Redis
- Telegram API
- Google API

---

# Presentation Layer

The layer responsible for exposing application functionality through REST API.

---

# Repository

An abstraction responsible for reading and writing domain entities.

Repositories hide implementation details of the database.

---

# Entity

A business object with a unique identity.

Example:

User

Organization

Project

Submission

---

# Value Object

An immutable object representing a business value without its own identity.

Example:

Email address

Phone number

Money

---

# Event

A business event describing something that has already happened.

Example:

SubmissionCreated

ProjectPublished

UserRegistered

---

# REST API

A collection of HTTP endpoints that expose FlowCore functionality.

---

# Multi-Tenancy

An architecture where multiple organizations share the same application while keeping their data completely isolated.

---

# Docker

The containerization platform used to package and deploy FlowCore.

---

# Swagger

Interactive API documentation automatically generated from the backend.
